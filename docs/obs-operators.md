# OBS: операторы, ключи и производительность

## Доступ операторов

1. Организатор заходит в /#/admin → «Аккаунты» и назначает сотруднику роль **Оператор эфира**.
2. Сотрудник входит в личный аккаунт (Steam или логин) и открывает /#/obs.
3. В блоке «Доступ операторов OBS» создаёт ключ для нужного OBS-компьютера, указывая понятное название и срок.
4. В появившихся ссылках к сценам есть параметр `obskey` **в URL-фрагменте после #**, поэтому он не попадёт в обычные access-логи прокси.
5. Ссылку нужной сцены вставляют в OBS Studio → «Источник Браузер» (1920×1080).
6. При увольнении/утере ключа организатор нажимает «Отозвать»; сцены перепроверяют доступ каждые 15 секунд.

**Безопасность:** ключ возвращается только при создании; сервер хранит SHA-256, срок действия, автора и время последнего использования. Ключ после обновления/закрытия вкладки не восстанавливается из API. Если ссылка утеряна, создайте новый ключ, старый отзовите. Не распространяйте рабочие OBS-ссылки публично. Старый общий ключ более не выдаётся.

**Полномочия:** роль obs_operator может изменять только состояние эфира. Изменение официальных результатов матчей остаётся доступным только admin/referee. Токен OBS разрешает только просмотр сцен, но не изменение состояния.

**Одновременная работа:** изменения пульта используют MariaDB GET_LOCK и expectedRev; если другой оператор уже изменил состояние, последняя попытка получит 409. Обновите состояние и повторите изменение. Это предотвращает молчаливую потерю записи. В случае разрыва сети клиент показывает последнее состояние эфира.

## Плавность и измерение

- CSS-переходы `steps()` заменены на плавную кривую для 35 анимаций.
- Анимируемые полноэкранные маски переключены с `clip-path` на композитную трансформацию; постоянно анимируемый большой SVG-контур отключён.
- Повторное обновление React при неизменном состоянии эфира подавлено, пересекающиеся запросы к API не накапливаются.
- Для отладки включите **`&perf=1`** к адресу сцены после `obskey=...`, например `#/obs/intro?obskey=...&perf=1`. Измеритель покажет RAF FPS, медленные кадры (>25 мс) и худшее время кадра. Убирайте `perf=1` из публичного эфира.
- Настройка источника: 1920×1080; общий FPS видео 60; аппаратное ускорение браузерного источника; не включать «Shutdown source when not visible» для непрерывной синхронизации, если нужно; ненужные источники скрывать.
- Для оценки: откройте intro, veto, draft, hud, stinger, fullscreen и измеряйте минимум 30 секунд после прогрева. Сравнивайте движение графики и OBS Stats → skipped frames и rendering lag. RAF FPS не гарантирует 60 FPS видеокодера.

## Деплой / откат

Production: `/opt/cup-src` → Vite dist → `/var/www/cup`, PHP в `/var/www/cup/api`.
Схема `obs_scene_keys` определена в `api/schema.sql`; миграция запущена отдельно без импорта данных.
Резервная копия: `/var/backups/cup/obs-operators-20261023-075550`.
После отката PHP **вернуть старые файлы API и index.html вместе**, иначе старый frontend и новый backend могут быть несовместимы.
Не удаляйте таблицу ключей при откате, она не влияет на остальные данные.
